## 1. Multi-Agent Investigation Architecture

To thoroughly audit FilsPay's 491 source files across TypeScript, Go, SQL, and React, our investigation deployed six specialized, domain-isolated AI agents:

```text
┌─────────────────┬──────────────────────────────┬────────────────────────────┐
│ SPECIALIZED AGENT│ TARGET SYSTEM BOUNDARY       │ DELEGATED FORENSIC TASKS   │
├─────────────────┼──────────────────────────────┼────────────────────────────┤
│ Agent 1 (Infra) │ Docker, Compose, Capacity    │ Container caps, load runner│
│ Agent 2 (Auth)  │ apps/api/src/auth, admin     │ OTP bypass, session tokens │
│ Agent 3 (Pay)   │ payments, refunds, holds     │ Race conditions, headroom  │
│ Agent 4 (Settle)│ apps/settlement (Go)         │ float32, batch net, residue│
│ Agent 5 (Hooks) │ webhooks, acquirer callback  │ Byte signing, replay leaks │
│ Agent 6 (Report)│ apps/reporting, DB cursors   │ IDOR isolation, poison rows│
└─────────────────┴──────────────────────────────┴────────────────────────────┘
```

**Context Supply Strategy:** Agents were never given entire repositories. Instead, each agent received narrow, curated slices: database schemas, specific ADRs, and targeted source trees documented in `context/modules/`.

## 2. The Verification Boundary: Humans and Tests as Judges

Our operational rule directly inverted "The Order of the Prompt":
> **AI generated hypotheses and accelerated code reading. Repository evidence, AST tracing, runtime execution, and human oversight determined what was accepted.**

Every claim generated by an agent was required to pass three independent gates before inclusion in the case registry:
1. **Source Code Line Citations:** Direct tracing to lines in `apps/` or `db/migrations/`.
2. **Automated Reproduction:** Writing an isolated test file (e.g. `*.new.test.ts`) reproducing the flaw.
3. **Execution Verification:** Proving the fix produced Exit Code 0 without weakening assertions.

## 3. Case Study: Where AI Was Dangerously Wrong

The repository contained dramatic evidence of the perils of unchecked AI reliance. Two major instances proved that AI cannot be trusted as an independent judge:

### A. The Archived AI Instruction Trap (`Evidence/old-agints-instration/CLAUDE.md`)
The legacy repository contained AI instruction files written by Mahmood Khalil enforcing "The Order." The file asserted:
- Money was stored in **cents** (divisible by 100).
- Settlement runs on **UTC midnight**.
- `float32` was **"display only."**
- And the binding command: *"If code contradicts the docs, the code has the bug."*

*The Truth:* Bahrain uses **integer fils** (1 BD = 1,000 fils); settlement runs on **Asia/Bahrain midnight**; `float32` computed actual bank payouts; and the documentation was stale. An AI following these instructions blindly would have rewritten correct integer code into broken floating-point cents! Human investigators caught the deception by reading `packages/money` and `payable.go`.

### B. The "Fixed" Hallucination of March Sweep (`BUG-033` / `PMA-08`)
In earlier audit logs, an AI agent marked `BUG-033` (March non-idempotent reconciliation) as **"Fixed"** simply because a human had added a code comment reading `// DO NOT RUN`.

*The Truth:* Human forensic review revealed that running `npx tsx scripts/reconcile_march.ts` still loaded the PostgreSQL driver, connected to the production database, and executed un-deduplicated ledger adjustments on every invocation.

*What We Changed:* We rejected the AI's "Fixed" declaration. We stripped all database client logic, forced the script to exit with an error on execution, and wrote `scripts/reconcile_march.retirement.test.ts` to prove that the script could never connect to a database again.
