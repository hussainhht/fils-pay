## BUG-013 — Hold cleanup deletes all holds

- **Classification / status:** Critical; verified, OPEN / NOT SOLVED. Current source matches the [canonical report](../bugs/bug-013-expire-holds-deletes-every-hold.md). Runtime proof reused; reproduction skipped under the plan.
- **Root cause / actual behavior:** Empty arrays remove the SQL predicate; an empty expired selection becomes an unrestricted DELETE. Nonempty selections also delete history and do not recheck eligibility after selection.
- **Affected files / technical evidence:** `scripts/lib/sqlFilter.ts:9-10,20,24-29` skips empty arrays and builds DELETE; `scripts/expire_holds.ts:17-25,43-45` selects active expired IDs and executes that builder without an empty guard. `db/migrations/0005_holds.sql:6-8` already supports status `expired`.
- **Existing evidence:** `Evidence/bugfix_plan.md`, Phase 0 already-proven list; `Evidence/runtime-artifacts/probe-results.ndjson:1`, P001: zero expired holds, SQL `DELETE FROM holds`, one live hold deleted.
- **Smallest proposed fix:** Empty IDs must match nothing in the shared builder. Replace cleanup deletion with a guarded UPDATE to `expired`, rechecking `status = 'active' AND expires_at < now()` in that statement; an empty set is a no-op.
- **Dependencies / limitations:** No schema change required. Coordinate capture/void eligibility handling (BUG-024/025); no configured cron schedule was independently verified. Comments claiming no-op/safe deletion are contradicted by executable SQL.

## BUG-081 — Migration drift and concurrency are unchecked

- **Classification / status:** Low; statically verified, OPEN / NOT SOLVED. [Canonical report](../bugs/bug-081-migration-runner-has-no-checksum.md) remains current. No defect inferred from numbering gaps or comments alone.
- **Root cause / actual behavior:** Applied state stores filenames only; changed contents are skipped. Separate migrators can read the same pending set without a migration-wide lock.

- **Existing evidence:** Canonical static report; `Evidence/FilsPay_Complete_Source_Code_Investigation.md:154,480,797`. BUG-014's existing migration artifacts demonstrate failure handling, not checksum/concurrency behavior; no new runtime claim made.
- **Smallest proposed fix:** Store and compare SHA-256 of applied migration contents before skipping. Separately serialize migrators with a session advisory lock held across discovery/application and released on exit.
- **Dependencies / limitations:** Coordinate BUG-014 before migration edits. Existing databases lack historical hashes: establish a trusted baseline before backfilling; hashing today's edited files cannot prove what previously ran. Checksums detect drift but do not apply corrections to already-recorded filenames; those still need forward migrations. No migration/checksum/lock changes implemented.
